# ADR-0004: socket2 for dual-stack networking

## Status
Accepted

## Context
awrust binds a single listener on port 4566 that must accept both IPv4 and IPv6 connections. On Linux (the Docker target), binding `[::]:4566` with `IPV6_V6ONLY=false` creates a dual-stack socket that accepts both families. On macOS (development), the same flag works but defaults differ.

Tokio's `TcpListener::bind` and the standard library's `std::net::TcpListener::bind` do not expose `set_only_v6(false)`, `SO_REUSEADDR`, or pre-bind nonblocking mode. To configure these options, we need access to the raw socket before binding.

## Decision
Use socket2 to create, configure, and bind sockets, then convert the resulting `socket2::Socket` into `tokio::net::TcpListener` or `tokio::net::UdpSocket` via their `from_std` constructors.

## Alternatives considered
- **Tokio's TcpListener::bind directly**: Does not expose `set_only_v6`. We would need to bind separate IPv4 and IPv6 listeners, doubling the accept logic and complicating the DNS responder (which also needs dual-stack UDP).
- **libc / nix crate (raw syscalls)**: Provides full control but requires unsafe code and platform-specific constants. socket2 is a safe, portable wrapper over the same syscalls.
- **Two separate listeners (v4 + v6)**: Avoids the socket2 dependency entirely, but doubles the listener count, complicates `select!` loops, and means the DNS responder also needs two UDP sockets. The complexity moves from one dependency to every call site.

## Consequences
Positive:
- Single listener per service (TCP and UDP) handles both address families
- Safe API — no raw `libc::setsockopt` calls
- Portable across Linux and macOS without conditional compilation
- Small dependency (~2 crates, no transitive tree)

Negative:
- One more dependency for what amounts to three socket options
- The `from_std` conversion requires the socket to be set nonblocking before handoff — a subtle invariant that would cause silent failures if missed

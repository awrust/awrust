# ADR-0005: tracing for structured observability

## Status
Accepted

## Context
awrust runs as a single process managing multiple child services inside a Docker container. When something goes wrong, the operator has one log stream to diagnose the issue. Logs must be machine-parseable (JSON) for Docker log drivers, filterable by severity, and carry structured fields (service name, listen address, error details) without string interpolation.

## Decision
Use `tracing` for instrumentation and `tracing-subscriber` (with `env-filter` and `json` features) for output formatting.

## Alternatives considered
- **log + env_logger**: The `log` facade is simpler but only supports unstructured string messages. Adding structured fields requires manual `format!` calls with ad-hoc key=value conventions that nothing enforces. `env_logger` outputs plain text, not JSON.
- **log + serde_json (manual JSON)**: We could format JSON ourselves using `log` macros and a custom logger. This re-implements what tracing-subscriber's JSON formatter already provides, including span context, timestamp formatting, and field serialization.
- **slog**: Supports structured logging natively, but has a smaller ecosystem than tracing and no span model. tracing's span-based context propagation is a better fit for async code where a single request crosses multiple `.await` points.
- **println! / eprintln!**: No filtering, no structure, no timestamps. Unusable for production diagnostics.

## Consequences
Positive:
- JSON output works with Docker log drivers, CloudWatch, and any log aggregator out of the box
- `EnvFilter` allows runtime control via `RUST_LOG` without recompilation
- Structured fields (`service = %target, error = %e`) are first-class — no string formatting
- Span context propagates across async boundaries, making it possible to trace a request through the proxy pipeline
- The same `tracing` macros work for both the facade and future service crates

Negative:
- tracing + tracing-subscriber add ~20 transitive crates
- The `tracing` macro syntax (`tracing::info!(key = %val, "message")`) is unfamiliar to developers coming from `println!`-style logging
- `EnvFilter` parsing failures panic at startup, which is intentional (fail fast on misconfiguration) but surprising
